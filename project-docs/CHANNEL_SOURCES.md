## 4. 2026-11-09 内容抽样与地址清理

### 4.1 触发原因与方法

用户反馈部分电视频道地址返回购物内容，因此单独进行内容抽样。这轮与前述来源文本核对、应用静态审查分别记录。

北京时间 2026-11-09 01:15～01:28，对清理前的 169 个地址执行有限时 HTTP／播放列表请求。124 路返回 HLS，逐路尝试下载一个分片并解码一帧，118 路得到画面，6 路因 HTTP 错误或超时未取得画面。

对可疑线路又进行后续复查，并重新请求首次记录的完整跳转目的地址以获取当前分片。原清单里的旧分片已返回 404，没有将后续画面当作旧时段的直接复现。工具为临时 curl / FFmpeg，不经过 Android 播放器；临时视频、截图和带签名参数的跳转地址没有打包或提交。

确认的目的流缺少对应频道台标，并出现与频道不符的全屏销售内容：

| 目的流路径 | 画面特征 |
| --- | --- |
| `/applive/102.m3u8` | 产品推销及咨询热线 `400-788-3916` |
| `/applive/yss.m3u8` | 半价购物及热线 `400-066-2600` |
| `/applive/mkt.m3u8` | 酒类订购及热线 `400-689-3979` |

判断结合解码画面及跨频道共用购物内容，不依据路径、主机名或一次 HTTP 成功下结论。以下跳转地址只记录 host / path，省略临时签名参数；时间均为当日北京时间。

### 4.4 判断与检查边界

删除依据是记录到的内容错配，不表示这些地址每次都会播放广告。正常台内广告、公益广告、夜间测试卡、地区限制、IPv6 不可达和超时没有单独作为移除理由。其余线路没有长期连续观察，抽到正确画面不代表未来始终正确或可播放。

该轮静态复核了目录数量、频道身份、非空源、标签顺序及只删除这 7 个地址的差异，并执行本地链接与 `git diff --check`。没有运行 Gradle、测试、Lint、安装、模拟器或真机任务；媒体抽样不等于 Android 端播放验证。
