## 2026-11-09：性能与正确性审查

### 触发原因

检查项目性能和其他缺陷，修正静态阅读可以确认的问题。该阶段没有调整依赖、Room schema、UI 框架或直播地址；地址清理独立记录在[来源专题](CHANNEL_SOURCES.md#4-2026-11-09-内容抽样与地址清理)。

### 修正内容

| 问题 | 修正 |
| --- | --- |
| 初始化任务依赖的字段写在启动逻辑之后，阅读顺序不清 | 在 `init` 前统一声明任务、请求代次和状态字段。已有编译缓存省略了默认值赋值，因此不将此项列为已确认的首次播放故障。 |
| 查询完成前连续换台，仍从已播放频道计算目标 | 按最新请求目标继续换台，取消过期加载。 |
| 频道缺失后旧视频继续播放，旧回调可能影响新请求 | 缺失态清空媒体；媒体 id 和业务请求代次核对。 |
| 临时空轨道清掉高度偏好，自动回落只改文案，选项含不支持格式 | 跳过过渡空轨道，逐轨道过滤并保留单档信息；回落也递增质量参数序号。 |
| 大目录搜索、抽屉过滤和状态合成在主线程，收藏变化重复创建索引 | 合成移到 Default，索引只随全集变化重建，抽屉结果去重后渲染。 |
| 收藏连点读取旧状态，旧任务清掉新覆盖；播放页旧写入返回值反写状态 | 覆盖同步取值并核对代次，写入按序提交；播放页只认仓库流。 |
| 同名多源去重反复扫描，导入前读取全部旧实体，计数可能失真 | 保序集合去重，`INSERT IGNORE` 返回真实新增数，减少正则和摘要编码分配。 |
| 多行裸 URL 被误当订阅地址，地址只校验 scheme，charset 参数不兼容 | 单行地址与正文分流，共用完整 URL 校验，兼容带引号和后续参数的 charset。 |
| 搜索恢复、导入窗口释放和画中画退出不完整 | 初始状态包含恢复词，回填后绑定监听，关闭时清 Binding，退出画中画显式恢复操作区。 |

### 检查与待验收

完成调用、取消和状态流的静态核对，读取 PlayerViewModel 缓存字节码辅助检查默认值赋值，对照缓存 Media3 1.11.1 API；执行差异格式、XML、11 个语言目录 key／占位符和本地链接检查。

新增 `M3uParserTest` 7 个 JVM 回归用例、`SourceCodecTest` 2 个 Android 用例、`ImportedChannelDaoTest` 1 个 Android 用例。只完成测试代码，未运行构建、测试、Lint 或设备任务，没有帧率、内存、起播速度或源可用性的实测结论。

待验收重点：首次播放、快速换台、缺失频道、限高回落、单档源、收藏连点、大目录筛选、多行 URL、重复导入、搜索恢复和前后台／画中画往返。

## 2026-11-09：播放页精简与文档折叠动画

### 触发原因

用户要求参考常见播放器减少观看遮挡，并移入参考项目的文档展开／收起动画。本轮没有新增依赖、播放业务或数据表。

### 播放页

- 顶底栏改用边缘渐隐遮罩，上一频道、频道列表和下一频道固定在底部，线路、画质、画中画集中到深色设置菜单。
- 菜单核对请求代次和选项，重复选择正常线路不重装；退后台、进入画中画或菜单失效时关闭根菜单及独立子菜单。
- 系统栏沉浸隐藏，边缘滑动临时唤出，按钮使用稳定 Insets；自动隐藏改为 3 秒、200ms 淡出和轻移，最后设为 `INVISIBLE`。
- 错误态、读屏、焦点、持续触摸和菜单期间保留操作区；频道提示只在控件隐藏时出现在顶部起始边缘，1.5 秒后淡出。

### 文档动画

参考 `RadioWorkshop/app/src/main/java/com/sugar/radio/ui/settings/VersionHistoryController.kt` 和拼图工坊的同类实现。每个章节 Holder 持有 `DocumentSectionAnimator`，以一个 240ms `fast_out_slow_in` 动画同步正文高度、透明度和箭头旋转。

反向操作从当前视觉状态接续；首次绑定、恢复、离屏、宽度变化和系统关闭动画时直接到目标状态。收起先退出焦点和读屏遍历，结束清除链接并恢复 `wrap_content`。章节定位等待 Diff、绑定、动画和布局稳定，回收与销毁取消旧回调；法律章节始终展开。

### 检查与待验收

当时静态检查包括：68 个 XML、344 处资源引用、4 份 Kotlin 的 ViewBinding、尺寸和 drawable 约束、55 个通用 key × 11 语言、24 个中文专用文案、8 份 Markdown 中 79 处链接／锚点和三份随包正文结构。另核对缓存 AppCompat 1.8.0 的菜单及深色主题实现。

没有构建、测试、Lint 或设备验证。待验收包括窄宽／短窗口、大字体、RTL、系统栏、键盘／遥控器／TalkBack、菜单期间自动换源、前后台与画中画，以及动画反转、回收、章节定位、系统关闭动画和重建恢复。

### 触发原因与最终行为

## 2026-11-09：设置菜单配色与播放卡顿排查

### 触发原因与修正

用户截图显示设置菜单为浅色底、白色字，同时反馈播放卡顿后自动换源。源码确认菜单只应用 AppCompat 深色文字主题，Material 弹窗背景仍继承浅色配置；播放逻辑此前未区分直播窗口落后与其他致命错误，均直接尝试后续线路。普通缓冲状态本身不会换源；没有现场日志，不能据此确定本次卡顿的根因。

- 设置菜单改用 Material3 深色覆盖，同时固定弹窗背景、文字、箭头、选中与禁用状态；根菜单与独立或级联子菜单复用背景。
- 直播窗口落后时先在原线路重新接入一次；恢复请求再次失败才顺序换源，末路仍保留 8 秒、最多 2 次的延迟重试。
- 缓冲、轨道和错误回调改用 Analytics 事件所属时间线读取媒体请求序号，避免旧媒体事件误归到新请求。
- 起播／重缓冲阈值由 800ms／1500ms 调整为 1500ms／3000ms，最小／最大仍为 15s／30s；实际阈值受 Media3 直播目标延迟限制，可能增加等待，没有实测改善结论。
- 调试包增加 `TvPlayback` 本机日志，记录缓冲时长、加载／致命错误、HTTP 状态、视频格式、带宽估计、掉帧与音频欠载；不记录地址、频道名、异常文本或堆栈，不落盘、不上报。排查步骤见[技术设计](TECHNICAL_DESIGN.md#76-卡顿与换源排查)。

### 检查与待验收

静态核对缓存 Media3 1.11.1 的 Analytics 回调与直播缓冲语义，以及 AppCompat 1.8.0 的子菜单样式传递、Material 1.14.0 的弹窗背景属性；检查 XML、资源引用、文档链接和差异格式。未运行 Gradle 构建、测试、Lint、安装、模拟器或真机任务，未请求直播地址。

待验收包括浅深色系统主题下的根菜单和两类子菜单、触摸／遥控器焦点、退后台／画中画菜单关闭、短时断流、直播窗口恢复及其重复失败上限。尚未复现用户设备上的卡顿，需结合连续 `TvPlayback` 日志区分网络／源加载、媒体解析与解码渲染问题。
